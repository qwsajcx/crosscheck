# 多模型协作最佳实践（tower / secondary_model / crosscheck）

> 适用版本：kimi-code ≥ 0.42（子代理模型池恒开；2.x 起实验开关已移除）。
> 定位：这是"什么时候用哪个多代理机制、模型怎么分层"的实战约定，源于 crosscheck 项目的实测记录（详见 DESIGN_BRIEF.md §10/§11）。

## 1. 模型分层：三层的钱怎么花

| 层 | 角色 | 选什么模型 | 为什么 |
|---|---|---|---|
| 编排层 | 主会话模型（派活、读状态、简报） | 便宜快（deepseek-flash / kimi-for-coding-highspeed 档） | 编排是轻量文本调度， token 大头在重读上下文，便宜模型省的是这个 |
| 战士层 | 修改者/审核者子代理 | 两个**不同**强模型（如 K3 max ↔ GPT xhigh） | 对抗价值来自视角差异；审核是质量闸门，档位不低于修改者 |
| 杂务层 | 池 `default_model` | 便宜模型 | 探索、摘要、批量小改等所有非关键子代理的兜底 |

池配置要点：

- **池描述写"选用场景"，不写"模型介绍"**——那是主代理选模型时唯一读到的文字。crosscheck 的 `setup_pool.mjs` 内置了修改者/审核者角色描述可直接用。
- **effort 用 `[models."<别名>".overrides] default_effort` 分别钉档**；不要设全局 `[thinking].effort`（它压过一切，全池同档）。
- **冒烟模型也入池**（deepseek-flash）：机制测试与正式审核共用一套配置，切换只改循环启动时的选择。
- 池是 per-user 全局的：配一次，所有项目受益。

## 2. 机制选型矩阵

| 需求 | 用什么 | 理由 |
|---|---|---|
| 聚焦小任务（读代码/小段修改） | `Agent` 单子代理 | 开销最小，上下文隔离 |
| 同目标大批量独立子任务 | `/swarm`（AgentSwarm） | 并行拆解、自带速率限制重试 |
| 项目多功能流并行推进 | `/tower`（实验） | worktree 分支隔离 + 多 worker；子代理继承主会话历史 |
| **关键文档/交付物的达标审核** | **crosscheck 插件** | 唯一带确定性验收契约的：结论行、新鲜度校验、角色互换、no-progress 判定、逐轮双文件提交 |
| 无人值守长时后台审核 | `legacy/review_loop.py` | tmux 黑盒，TUI 关了也能跑 |

判断口诀：**"宽"用 swarm/tower（并行推进），"深"用 crosscheck（对抗收敛）**。

## 3. 交叉审核在项目流水线中的位置

```
tower/swarm 并行推进功能 ──产出方案/文档──▶ crosscheck 对抗收敛 ──PASS──▶ 合入主线
                                              │ FAIL 循环（≤10 轮兜底）
                                              ▼
                                        到顶/no-progress → 人工介入
```

纪律条目（都是实测换来的）：

1. **双模型是硬要求**：单模型自审不收敛——修补链每轮引入次级缺陷 + 边缘意见振荡（实测 10 轮跑满不收口）。
2. **只给值得的文档上循环**：需求稿、方案、对外接口契约、发布说明值得；随手笔记不值得。循环不便宜（一次深审 20-46 分钟）。
3. **同一文档同一时刻只跑一个循环**：两个循环并发读写同一审核文件会双向污染（2026-08-09 撞车实录）。
4. **循环跑专用分支**：逐轮提交只含"文档 + 审核意见"两个文件，主线不受打扰，历史可读。
5. **审核者档位 ≥ 修改者**：审核是质量闸门，别让弱模型给强模型放水。
6. **到顶交人工**：max-rounds / no-progress 是"需要人看最后一版意见"的信号，不是重跑信号。

## 4. tower 使用细则（实验期，语义仍在变）

- 开启：`/experiments` 面板勾选或 `KIMI_CODE_EXPERIMENTAL_TOWER=1`；`/tower on` 后 `/tower <目标>` 启动；`/tower <base-branch>` 指定基线分支。
- 干预方式：运行中直接发消息即中断当前回合并执行新消息（2.2 起）——比暂停/恢复轻量。
- 注意子代理**继承主会话历史**：worker 上下文与主会话一致（沟通损耗低），但长会话会让每个 worker 都背个大上下文——推进项目时保持主会话精简。
- 实验期警告：web 优先、TUI 能力滞后，roster/steering 语义近两个版本都在改。**关键验收不要依赖 tower**，验收走 crosscheck 的确定性契约。

## 5. 成本配比参考（实测）

编排层约占总开销 5-10%，战士层（尤其审核深读）占 90%+。省钱的正确姿势是压缩编排层模型档位 + 控制审核文档清单，**不是**给战士降档——降档省的是小钱，丢的是对抗质量。

## 6. 恢复与故障

- 任何循环中断（关会话/429/压缩）：状态文件是唯一事实来源，新会话说"继续 crosscheck"。
- 429 分两类：瞬时拥塞退避重试；配额耗尽等窗口重置（5h 滚动/月度），别空烧轮次。
- 子代理声称"已到终态"：一律 `verdict` + `git log` 核对，不信口述。
